# OmniGuard AML — V2 roadmap (future work, in priority order)

Nothing here is started. Each item lists why it was deferred and what unblocks
it. Sources: DECISIONS.md D-items, README limitations, PRD §13.

## 1. M1 — Automated promotion gates
**Why deferred:** promotion is currently a human reading MLflow.
**Shape:** `models/meta.json` gains a `champion` block; `train.py` promotes
iff held-out F1 beats champion by >0.02 with no recall regression; writes
`audit.model_promotions` receipt (table already in DDL, unwritten) or logs a
rejection. **Unblocks:** safe retraining cadence.

## 2. M2 — Drift monitoring
**Why deferred:** needs the training snapshot M1 standardizes.
**Shape:** `scripts/drift_check.py` — PSI per top-SHAP feature vs snapshot
(alarm >0.25), analyst-override rate vs recommendations (alert >30%/week),
`pol_ok` trend (prompt/policy drift), append-only `drift_reports` table.
**Unblocks:** knowing when the world moves under the model.

## 3. Bigger ledger + harder eval
**Why deferred:** 8 GB box; IBM 8.2 GB set doesn't fit; PaySim account-first
sample (3,609 txs) is the current scale.
**Shape:** bigger iron → full PaySim/IBM-HI ingestion via the existing loader
pattern, 50-case suite scaled up, re-measure everything.
**Unblocks:** production-credible scorer numbers.

## 4. Paid NIM tier
**Why deferred:** free-tier congestion/stalls + entitlement limits (552B
unservable, 5 fallback candidates 404).
**Shape:** paid key → re-enable 552B reasoning, re-run live eval, compare
cost/latency/quality vs the 120B+30B chain. **Unblocks:** live quality story.

## 5. Real KYC feed
**Why deferred:** challenger exoneration runs on synthetic KYC (noise).
**Shape:** ingest real customer/purpose/parent-entity data; challenger becomes
informative instead of random; re-measure lookalike FPR. **Unblocks:**
trustworthy CLOSE recommendations.

## 6. Hybrid RAG retrieval
**Why deferred:** 18-note corpus — dense+HNSW plus tag filter wins cheaply.
**Shape (gated):** enable only when corpus >100 notes AND dense-only misses
exact-term queries in eval → add `tsvector`+GIN, BM25+dense RRF fusion,
labeled retrieval eval, ship only on measured win. Transactions stay
exact-SQL forever.

## 7. PRD v2 leftovers (unsequenced)
Kafka/Flink streaming ingestion · GNN on Neo4j (past NetworkX plateau) ·
OSINT/sanctions APIs + NER · UBO resolution pipeline · RBAC/multi-tenant ·
SAR export (FinCEN XML) · React polish (audit-trail tab needs a list endpoint).
